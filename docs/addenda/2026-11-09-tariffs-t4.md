# Тарифная система, этап T4: смена тарифа, период и цена, предупреждения

Платёжные интеграции не подключены: оплату периода подтверждает администратор платформы вне
системы, система хранит период и его цену. Логика не привязана к названиям, числу и ценам
тарифов; бесплатные тарифы архивируются как любые другие.

## Правила
1. **Смена тарифа не трогает `CompanyModule`.** Вручную отключённые модули сами не включаются;
   владелец сам выбирает, подключать ли новые модули тарифа. Тест: расширение и сужение состава
   тарифа, смена тарифа - набор включённых модулей не меняется.
2. **Повышение:** новые модули, функции и лимиты доступны сразу - всё читается из тарифа в момент
   обращения, никакой отдельной «активации» нет.
3. **Понижение:** данные не удаляются. Сверх нового лимита блокируется только создание новых
   объектов; просмотр, правка, расчёты и удаление существующего сохраняются. Модуль, которого нет
   в новом тарифе, закрывается для работы, данные и `CompanyModule` остаются. Перед сменой
   администратор видит анализ последствий (`change-plan/preview`): какие модули закроются,
   какие функции и модули появятся, какие лимиты уже превышены (с фактическим использованием) и
   какие стали жёстче.
4. **Предупреждения владельцу:** `GET /api/billing/usage/` отдаёт по каждому лимиту использование и
   состояние `ok / near / reached / exceeded`, а также список `warnings`. Порог «приближается» -
   настройка тарифа `limit_warn_percent` (0 - не предупреждать заранее). В интерфейсе: баннер для
   пользователей с правом `company.manage_modules` и блок «Лимиты тарифа и использование» на
   странице компании.
5. **Стоимость и бесплатный период - данные тарифа:** `price`, `currency` (T1), `free_period_days`
   (срок бесплатного периода новой компании на этом тарифе, 0 - нет). Прежняя константа 365 дней
   перенесена в тариф по умолчанию (поведение прежнее), в коде её больше нет.
6. **Цена оплаченного периода неизменна:** при начале периода пишется неизменяемая запись
   `SubscriptionPeriod` (тариф, срок, цена, валюта, бесплатный или нет). Изменение цены тарифа её
   не меняет. Новая цена применяется при продлении (`renew`: новый период от конца текущего или с
   текущего момента, цена тарифа на момент продления, несколько периодов - сумма) и при смене
   тарифа с `period=restart` (новый период по цене нового тарифа). По умолчанию `period=keep`:
   действующий период, его срок и цена сохраняются до окончания, новая цена - при продлении.
   Возвратов и пересчётов нет (платежей нет).
7. **Линейка тарифов - данные:** тариф по умолчанию для новых компаний берётся из данных; архивный
   тариф продолжает работать у подключённых компаний.

## API администратора платформы
- `GET /api/platform/subscriptions/{company}/` - подписка, текущий период и история периодов.
- `GET .../change-plan/preview/?plan=код` - анализ последствий (без изменений).
- `POST .../change-plan/ {plan, period: keep|restart}` - смена тарифа (аудит с последствиями).
- `POST .../renew/ {periods: 1..24}` - продление; бессрочная подписка не продлевается.
- Тариф: `free_period_days`, `limit_warn_percent` правятся `PATCH /api/platform/plans/{code}/`.

## Не в T4
Самообслуживание владельца (смена тарифа и оплата) - после согласования платёжных интеграций;
панель администратора - T5; уведомления по почте/мессенджеру - модуль уведомлений.
Восстановление объекта из корзины не считается созданием и лимитом не проверяется.
