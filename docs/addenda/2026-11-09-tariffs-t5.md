# Тарифная система, этап T5: административная панель владельца платформы

Панель доступна только администратору платформы (`is_platform_admin`), раздел меню «Платформа»;
шлюз подписки собственной компании администратора на неё не влияет. Всё, что настраивается,
хранится в данных; платёжные интеграции и платная инфраструктура не подключены.

## Разделы
- **Тарифы** (`/platform/plans`): список всех состояний с числом подписок, порядок (↑ ↓),
  создание и правка в карточке с вкладками «Основное» (название, описание, цена, валюта, период,
  бесплатный период, порог предупреждения о лимите), «Модули и функции» (модули с автоматическим
  учётом зависимостей, функции: включено/уровень; функция недоступна без модуля) и «Лимиты»
  (значение или пусто = без ограничений). Действия: опубликовать, снять, назначить по умолчанию,
  в архив, из архива, удалить (только без подписок). Ошибки сервера показываются в панели.
- **Подписки компаний** (`/platform/companies`): поиск компаний; карточка подписки с текущим
  периодом и ценой, историей периодов, сменой тарифа с анализом последствий (какие модули
  закроются и появятся, какие лимиты уже превышены с фактическим использованием, цена) и выбором
  «сохранить период / начать новый», продлением.
- **История изменений** (`/platform/history`): кто, когда, что изменено (было → стало) по тарифам
  и подпискам, фильтры по объекту и коду.

## Серверная часть
- Журнал `BillingEvent` (неизменяемый): создание, изменение (только реально изменившиеся поля),
  публикация, снятие, архив, возврат, назначение по умолчанию, удаление, порядок, смена тарифа
  компании, продление; хранится автор (снимок email). API: `GET /api/platform/history/`.
- `GET /api/platform/companies/` - компании с подписками (поиск, страницы).
- Сессия отдаёт `user.is_platform_admin`; пункты меню `platformOnly` и маршруты закрыты для
  остальных (сервер проверяет всё равно).

## Корзина и лимиты
Восстановление из корзины проверяется по лимитам тарифа так же, как создание, для всех типов,
учитываемых лимитами: при превышении - `402 limit_exceeded` (`action: restore`) с понятным
сообщением, объект остаётся в корзине; просмотр корзины доступен; после повышения тарифа
восстановление проходит. Объект месячного лимита, созданный в прошлых месяцах, лимит текущего
месяца не занимает. Проверка в `SoftDeleteModel.restore()`, поэтому охватывает любой путь.
