# Тарифная система, этап T2: модули и функции тарифа

Тариф определяет доступные модули и функции; профиль компании лишь рекомендует стартовый набор
модулей. Они не связаны жёстко. Всё настраивается администратором платформы через API без
изменения кода. Лимиты - этап T3.

## Что реализовано
- Состав тарифа в данных: `Plan.modules` (список модулей) и новое `Plan.features` (функции
  внутри модулей). Правятся `PATCH /api/platform/plans/{code}/` (`modules`, `features`), доступны и
  при создании. Справочник возможного: `GET /api/platform/catalog/` (модули с зависимостями,
  функции с видом и уровнями).
- Правила состава: известные не-core модули без повторов; жёсткие зависимости модуля обязаны быть
  в тарифе (finance требует logistics и т.д.), искусственных связей нет (documents без finance,
  fleet без forwarding); функция модуля допустима, только если модуль в тарифе; убранный из тарифа
  модуль убирает свои функции; выключенные функции не хранятся.
- Каталог функций в коде (`apps/billing/features.py`): белый ярлык, собственный домен, уровень
  аналитики, API и интеграции (уровни), автоматизация, история и отчёты, несколько филиалов,
  приоритетная поддержка. Значение - true/false либо уровень по возрастанию. Каталог - то, что
  код умеет проверять; какие из них и на каком уровне входят в тариф - данные.
- Серверная проверка: `has_feature(company, код, мин. уровень)` и DRF-право `FeatureRequired`
  (403 `feature_unavailable`). Функция доступна, если она есть в тарифе И модуль-владелец включён у
  компании. `/api/session/` отдаёт доступные компании функции (`features`).
- Модули по-прежнему проверяются на сервере (`ModuleRequired`): тариф И `CompanyModule`.
- Прежние `white_label`/`custom_domain` из служебных `options` перенесены в `features`
  (миграция `billing.0007`); публичный контракт тарифа отдаёт `features` вместо `options`.

## Сохраняется
- `CompanyModule` - источник истины о подключённых модулях; смена состава тарифа его не меняет
  и никогда не включает вручную отключённые модули; применение профиля вручную отключённые тоже
  не включает (`manually_disabled`).
- Данные при отключении модуля (владельцем или сужением тарифа) не удаляются; доступ возвращается
  при возврате модуля в тариф и включении.
- Владелец по-прежнему может включать дополнительные модули в рамках тарифа и отключать их.

## Не в T2
- Количественные и технические лимиты - T3; смена тарифа компании, предупреждения о понижении,
  привязка цены к подписке - T4; административная панель - T5; платные дополнения и оплата.
- Функции из каталога подключаются к конкретным операциям по мере появления самих возможностей
  (аналитика, интеграции, автоматизация, филиалы). Сейчас механизм готов, но ни одна операция
  его не вызывает. Предложение к согласованию: привязать `white_label` к редактированию брендинга
  (изменит поведение для тарифа «Старт», где функция выключена).
