# Приёмочный сценарий в браузере (тестовые данные) и результаты

Сценарий выполняется на тестовых компаниях; повторяется на целевом окружении после выкладки (`LAUNCH.md`, п. 7).

## Как проводилась проверка (2026-11-09)

Локально: временная БД, миграции под владельцем БД, приложение под ролью `logistix_app`
(NOSUPERUSER NOBYPASSRLS, RLS принудительно включён, `check_rls`: 49 таблиц компаний), backend `runserver`,
frontend Vite dev-сервер, браузер Chromium (Playwright). Данные вымышленные: владелец платформы и компания
«Альфа» (один аккаунт), компания «Бета» (отдельный администратор), сотрудник «Менеджер» компании «Альфа».
Режим учёта `legacy` (по умолчанию). **Не проверялось в этой среде:** сборка docker-образов, nginx, реальный TLS
и CSP боевого nginx (консоль браузера проверена на dev-сервере), производительность.

## Наблюдения для решения заказчика

1. **Режим `legacy`: «К оплате перевозчику» не входит в прибыль месяца автоматически.** После двух заказов по 250 000 с
   рейсами по 180 000 финансовая сводка показала прибыль 500 000 и маржу 100 %. Расход перевозчику в этом режиме учитывается
   только строками расходов заказа (вкладка «Финансы» заказа); автоматическая синхронизация `carrier_price` в расход работает
   только при `engine=new`. Для запуска нужно решить: вносить расход перевозчику строкой заказа вручную в `legacy` либо
   включать `engine=new` после проверок 3-7 (отдельное разрешение). Код не менялся.
2. Колонка «К оплате перевозчику» в списке рейсов уходит за правый край на узком экране (таблица прокручивается). Исправление
   вёрстки не критично для запуска.
