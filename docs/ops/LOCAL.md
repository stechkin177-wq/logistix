# Локальный запуск LogistiX с тестовой базой (вымышленные данные)

Всё работает только на вашем компьютере (127.0.0.1): никаких публикаций, внешних баз, реальных
аккаунтов и компаний. Тестовые данные, пароль и ключ TOTP - учебные.

## Что нужно один раз
- **Python 3.12+** и **Node.js 20+** (`python --version`, `node --version`);
- **Docker Desktop** (PostgreSQL 16 в контейнере) - либо свой локальный PostgreSQL 16 с ролью `logistix` /
  паролем `logistix` и утилитой `psql` в PATH (тогда добавляйте ключ `--no-docker` к каждой команде ниже);
- репозиторий и ветка `claude/epic-bohr-380x91`.

## Запуск (3 шага)
В корне репозитория:
```bash
python local/run.py start
```
Первый запуск сам: поднимает PostgreSQL, создаёт базу `logistix_demo` и роль приложения без обхода RLS
(изоляция компаний работает так же, как в продакшене), ставит зависимости, выполняет миграции, создаёт
тестовые данные и запускает backend (`:8000`) и frontend (`:5173`). Занимает несколько минут; повторные
запуски - секунды. На Windows используйте `python` (или `py`) вместо `python3`.

Откройте **http://127.0.0.1:5173**. Остановить: `Ctrl+C`; PostgreSQL в Docker: `python local/run.py stop`.

## Вход (один аккаунт - оба режима)
1. Логин `owner@demo.local`, пароль `Demo-pass-2026!`.
2. Второй шаг - код TOTP. Без телефона код выдаёт команда (в другом окне терминала):
   ```bash
   python local/run.py totp
   ```
   (код действует ~30 секунд и принимается один раз; следующий вход - следующий код). Либо добавьте ключ из вывода
   `seed_demo` в приложение-аутентификатор (Google Authenticator, Aegis, FreeOTP).
3. Вы в режиме **«Владелец платформы»** (`/platform`: тарифы, подписки компаний, история).
4. Переключатель внизу слева: **«Администратор компании»** открывает компанию «ИП Демо-Перевозчик (тест)» без повторного
   входа; **«Владелец платформы»** возвращает в платформу (потребуется свежий код TOTP).

## Другие демо-аккаунты (пароль тот же)
| Логин | Роль |
|---|---|
| `manager@demo.local` | Менеджер компании А |
| `accountant@demo.local` | Бухгалтер компании А |
| `admin@b.demo.local` | Администратор компании Б («ТОО Демо-Экспедитор (тест)») - для проверки изоляции |

## Что есть в тестовых данных
Компания А (режим учёта `legacy`): 4 клиента, 3 привлечённых перевозчика, техника (3 тягача/грузовика, 2 прицепа),
3 водителя, документы техники и водителей с разными сроками (есть просроченные и скоро истекающие), заправки, плановое ТО,
5 заказов и 3 рейса: завершённый (сценарий «ставка клиента 250 000, к оплате перевозчику 180 000, расход внесён» - прибыль заказа
70 000), собственный в пути и запланированный; 2 заказа ждут рейса. Компания Б: 1 клиент и 1 заказ.

## Что попробовать
- Платформа: тарифы (состав, лимиты), подписки компаний, блокировка и возврат компании, журнал.
- Заказ -> «Создать рейс» -> статусы кнопкой «следующий шаг» -> финансы (сводка, счета, расходы).
- Расход перевозчику: «Финансы» заказа (строка с полем «Рейс») или кнопка в форме счёта перевозчика; повтор блокируется.
- Роли и права: войдите менеджером и бухгалтером, сравните меню; зайдите компанией Б и убедитесь, что чужих данных нет.
- Техника и водители: предупреждения по документам, типы документов (Настройки -> Типы документов).

## Начать заново
```bash
python local/run.py reset      # удалит тестовую базу и создаст заново (данные вымышленные)
```

## Если что-то не так
- `Не найден «docker»` - установите Docker Desktop или используйте `--no-docker` со своим PostgreSQL.
- Порты 8000, 5173 или 5432 заняты - освободите их (в Docker-режиме PostgreSQL использует 5432).
- После долгой паузы вход просит снова пароль и код - это нормально (токены ограничены по времени).
- Код TOTP «неверный»: он принимается один раз и только в окне ±30 секунд; запросите новый и введите сразу.
