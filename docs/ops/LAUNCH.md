# Подготовка к запуску первых компаний (не зависит от провайдера)

Документ описывает порядок и чек-листы. **Ничего из раздела «Выполнение» не запускается без отдельного
разрешения заказчика**: деплой, миграции на целевой базе, создание реального владельца платформы и первой
компании, слияние в `main`, переключение `engine=new`. Провайдер хостинга пока не выбран; команды ниже
не привязаны к нему (детали сервера, DNS, TLS, nginx - `docs/ops/RUNBOOK.md`). До 100 одобренных компаний
используются только бесплатные сервисы и инфраструктура; платные подключения - только по отдельному
согласованию.

## 1. Что должно быть решено до выкладки (решения заказчика)

- [ ] Площадка: где работают первые компании (сервер с Docker, домен, TLS). Демо на бесплатных тарифах Vercel/Neon
  допускает только вымышленные данные (`docs/ops/VERCEL.md`, правило №1) и для реальных компаний не подходит.
- [ ] Хранилище бэкапов на территории Казахстана (раздел 8 RUNBOOK), ключ шифрования хранится отдельно.
- [ ] Режим учёта: первые компании работают на `engine=legacy` (по умолчанию). `engine=new` - только после
  проверок 3-7 из `docs/decisions/2026-11-07-g0-clarifications.md`, отдельно для каждой компании.
- [ ] Кто администратор сервера (сброс пароля и TOTP, раздел 13 RUNBOOK) и кто первый владелец платформы.

## 2. Проверки до выкладки (можно выполнять сразу, ничего не меняют в рабочей среде)

- [ ] CI зелёный на коммите релиза (backend: все тесты, RLS-скрипты, проверка миграций; frontend: tsc, eslint, vitest).
- [ ] Релиз идёт из ветки/тега, согласованных заказчиком (слияние в `main` - только с его разрешения).
- [ ] `deploy/.env.prod` создан на сервере вручную (права 600), все dummy-значения заменены, пароли БД разные и случайные,
  `DJANGO_DEBUG=false`, `TRUST_PROXY_HEADERS=true` только за своим nginx (раздел 12 RUNBOOK).
- [ ] Бесплатные сервисы: Sentry выключен (`SENTRY_DSN` пуст) или собственный; внешних API нет.

## 3. Выполнение (только с разрешения заказчика)

Каждый шаг отмечается и сохраняется вывод команд. Остановиться при первой ошибке, не продолжать «в обход».

1. **Бэкап** текущего состояния, если база уже существует: `./deploy/backup.sh` (код выхода 0).
2. **Выкладка:** `./deploy/release.sh vX.Y.Z` (раздел 4 RUNBOOK). Ожидается: `migrate` завершён с кодом 0,
   внутри него `check_rls` под ролью приложения без нарушений.
3. **Проверка выкладки:** `SMOKE_CHECK_HEADERS=1 ./deploy/smoke.sh https://<домен>`; `./deploy/dc.sh ps` (все сервисы
   healthy); `manage.py check --deploy` (допустимо только security.W004 при выключенном HSTS);
   в браузере открыть страницу входа, консоль без ошибок CSP.
4. **Аккаунт владельца и своя компания (один аккаунт на оба уровня)** - по `docs/ops/OWNER_ACCOUNT.md`: сначала
   `create_platform_owner` (без пароля, печатает одноразовую ссылку), затем `bootstrap_company --allow-existing-user
   --profile <код>` для той же учётной записи; владелец сам задаёт пароль по ссылке и подключает TOTP при первом входе.
5. **Центр управления:** войти владельцем, проверить тарифы (цена, период, бесплатный период, состав модулей и
   лимиты - это данные, а не код), тариф по умолчанию опубликован.
6. **Другие компании** (по заявкам): `bootstrap_company --profile <код>` с новым администратором; пароль
   администратору - также через `issue_password_link` (без передачи пароля).
7. **Приёмка на реальном окружении** по `docs/ops/ACCEPTANCE.md` (заказ -> рейс -> финансы, права, изоляция двух
   компаний) на тестовых компаниях; тестовые компании после приёмки блокируются владельцем платформы.
8. **Резервная копия после первичной настройки** и проверка восстановления на отдельной базе (раздел 8 RUNBOOK).

## 4. Откат

- Код/образы: предыдущий тег (`deploy/.previous_tag`), раздел 7 RUNBOOK.
- Схема: только восстановление базы из бэкапа до выкладки (раздел 7); `migrate` назад без бэкапа не предусмотрен.
- Если после выкладки не работает вход: `manage.py reset_totp`/`changepassword` (раздел 13), проверка `ALLOWED_HOSTS`/CORS/CSRF
  для домена.

## 5. Не входит в запуск (отложено по решению заказчика)

`engine=new`, Support Access, управление персоналом платформы из интерфейса, вложения и файловое хранилище,
GPS/OCR/Telegram/уведомления, мобильный интерфейс водителя, платёжные и почтовые интеграции, лента событий техники.

## 6. Ограничения, о которых нужно знать при первом запуске

- Образы `Dockerfile.backend`/`Dockerfile.web`, `nginx -t`, TLS, `docker compose up` целиком, GitHub Actions deploy и выгрузка
  бэкапов в реальной среде ещё не проверялись (список в RUNBOOK, «НЕ проверено»); первая выкладка - это их проверка.
- Один сервер без отказоустойчивости; лимиты gunicorn/памяти не нагружались.
- Восстановление пароля только администратором сервера (почты нет).
