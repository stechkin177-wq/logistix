## Интерпретации и решения без явного указания в ТЗ

1. **«Старые поля `load`/`unload`».** В действующем API груза такого поля нет: маршрут задаётся списком `points` (load + unload). Сохранено именно оно (чтение - первая погрузка и последняя выгрузка, запись - крайние остановки). Ключи `load/unload` сохранены в контексте документов.
2. **`seq` в записи `stops`** не принимается (только чтение): порядок задаёт порядок списка. Сервис перенумерации выполняет сдвиг через временные номера (20001+), поэтому unique(груз, seq) не нарушается на ходу.
3. **`seq` по умолчанию 0** + автоназначение следующего номера в `save()`, если не задан (для прямого создания в тестах/скриптах); CHECK `seq >= 1` страхует пропуск.
4. **Ограничения маршрута** (по ТЗ - в сервисе, не в БД): минимум 2 и максимум 50 остановок; в середине допустимы любые виды (в том числе вторая погрузка/выгрузка); окна по порядку между остановками не сравниваются, только `window_from <= window_to` внутри остановки.
5. **Статусы и время остановок** (`status`, `arrived_at`, `done_at`) пока только записываются через `stops` без автоматических переходов; события и `location_status` - этап D.
6. **Миграция схемы B разбита на три файла** (0008/0009/0010): уникальность (груз, seq) нельзя добавить до заполнения seq.
7. **Загрузка окна `loading_from/to`** в списке заказов считается по первой (по seq) погрузке каждого груза.
8. Доли на остановке проверяются только против количества груза; согласование с долями участков - этап C.

## Оговорки и известные ограничения

- Откат 0008 невозможен при наличии промежуточных остановок / нескольких погрузок или выгрузок (защита вместо удаления данных).
- Интерфейс «Несколько остановок» не отображает в списках заказов более одной пары городов (по ТЗ: список и экспорт показывают первую погрузку и последнюю выгрузку).
- Остановки в корзине отдельно не учитываются (удаляются каскадом вместе с грузом при физическом удалении, как и раньше).
