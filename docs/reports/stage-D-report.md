## Что сделано

**D1. `CargoTransfer`** (tenant, RLS): consignment (PROTECT), `from_trip`/`to_trip` (null, `to_trip` необязателен, фиктивные рейсы не создаются), `from_stop` (null), `to_stop` (остановка вида `transfer`), `transfer_kind` (to_carrier, between_vehicles, to_storage, from_storage), `from_carrier`/`to_carrier` (копия на момент передачи; выводятся из рейсов, для `to_carrier` без рейса задаются явно), `carrier_changed`, `transferred_at`, количество (null = весь груз), `status` (initiated, confirmed, reversed), `initiated_by`, `source` (manual|driver_app), `confirmed_by/at`, `reverses` (сторно), `note`, `created_at`. Неизменяемость: `save()` модели допускает только правку инициированной записи (подтверждённая и сторно - `ImmutableRecordError`), `delete()` запрещён; сервис исправляет только записью-сторно. Валидации: остановки принадлежат грузу; `to_stop.kind == transfer`; при `from_trip` у груза есть неотменённый участок этого рейса, заканчивающийся на `to_stop`; при `to_trip` - участок, начинающийся на `to_stop`; количество не больше количества груза; `carrier_changed` - перевозчики рейсов известны и различаются.

**D2. `ConsignmentEvent`** (tenant, RLS, только добавление, запрет правки/удаления). `record_event` обновляет статус остановки (`arrived_at`/`done_at`/`status`), вызывает `recompute_location` (единственное место записи `current_stop` и `location_status`: planned, in_transit, at_stop, in_storage, delivered), идемпотентен по ключу (груз, остановка, вид, время) - повтор возвращает прежнее событие и ничего не меняет (в БД - уникальный индекс). GPS не привязывается. Подтверждение передачи само пишет событие на `to_stop` (`stored`/`loaded`/`transferred`). Местонахождение также пересчитывается при создании/переназначении/смене статуса/удалении рейса (`refresh_tracking`), независимо от engine.

**D3. Права.** `consignments.transfer` - отдельный список каталога (не в общих extra-списках): Администратор, Менеджер, Диспетчер. Миграция core.0019 независима, идемпотентна, самодостаточна, обратима как noop; назначается другим ролям штатно через `/api/roles/` (выше своих прав выдать нельзя - действующий механизм). Подтверждение и сторно требуют `consignments.transfer`; инициировать можно с `consignments.transfer` или `consignments.update` (`permission_any`), сервис принимает `source='driver_app'`; событие - `consignments.update`; чтение - `consignments.view`. Все действия пишутся в аудит (create передачи/события, update при подтверждении, create сторно).

**D4. API и интерфейс.** `GET/POST /api/consignments/{id}/events/`, `GET/POST /api/consignments/{id}/transfers/`, `POST /api/transfers/{id}/confirm/` и `/reverse/`, `GET /api/transfers/` (фильтры consignment, order, trip, status, kind, pending). В ответе груза `location_status`, `location_status_name`, `current_stop` (только чтение), фильтр списка грузов `?location_status=`. ## Интерпретации и решения без явного указания в ТЗ (для подтверждения заказчиком)

1. **Сторно.** Статус `reversed` получает сама запись-сторно (`reverses` = исходная); исходная остаётся `confirmed` (иначе нарушилась бы неизменяемость). «Отменена» вычисляется (`reversed_by` в API). Сторно допустимо и для ещё не подтверждённой (инициированной) записи - это её отклонение; сторно сторно и повторное сторно запрещены (уникальный индекс).
2. **`to_stop` обязателен** для всех видов (для `from_storage` - остановка-склад, где груз берут), `from_stop` необязателен.
3. **Правила видов:** `to_storage` - без `to_trip`; `from_storage` - с `to_trip` и без `from_trip`; `between_vehicles` - оба рейса; `to_carrier` - принимающий перевозчик из `to_trip` или явный. Явный перевозчик, противоречащий рейсу, отвергается.
4. **`in_storage`** = последняя (по времени передачи) подтверждённая передача без сторно имеет вид `to_storage` и от её остановки нет назначенного исходящего участка. Приоритет статусов: delivered > in_storage > at_stop > in_transit > planned. `delivered` - последняя остановка выполнена или завершён участок, заканчивающийся на ней.
5. **События:** остановка обязательна (или выводится из участка); `delivered` - только на остановке выгрузки; `arrived/loaded/unloaded/transferred/stored` переводят остановку в «прибыли», `departed/delivered` - в «выполнена», `skipped` - в «пропущена» (выполненную пропустить нельзя). Ключ идемпотентности - (груз, остановка, вид, время).
6. **Миграция 0014** заполняет `location_status` у существующих грузов по остановкам и участкам (журнал событий начинается с момента включения, как в addendum).
7. **Права видимости.** Список передач и ленты читаются с `consignments.view` под модулем `forwarding`; инициирование - `consignments.transfer` ИЛИ `consignments.update`.
8. **Остановки с передачами/событиями** защищены PROTECT (как с участками): удалить такую остановку нельзя.
9. **Frontend:** «карточка груза» - блок груза во вкладке «Грузы» заказа (отдельной страницы груза нет); рейсы в диалоге передачи вводятся по id (поиск рейсов не добавлялся); вид, остановка и время - выбором.
