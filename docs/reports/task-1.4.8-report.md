## Реализация
- `migrate_order(order, run, overwrite, dry_run)`: все строки заказа (в т.ч. удалённого/отменённого). Доход: Income(legacy_line, recognized, `legacy_line_date`, recognized_on = дата строки, freight для базовой строки, иначе service, валюта заказа; FX на дату строки, нет курса или базовой валюты -> `legacy_missing`, курс не придумывается). Расход перевозчика: группа по title, проходит только при всех условиях (рейс есть и не удалён, есть перевозчик, заказы из состава рейса, валюта = валюте рейса, нет второй группы на тот же рейс/уже существующего расхода, суммы > 0) -> один Expense (`carrier_transport`, `migrated`, `trip:{id}`, Σ строк, мин. дата, `needs_review/migrated_mismatch` при Σ != carrier_price) + доля на каждую строку с legacy_line. Любое сомнение -> Issue `ambiguous_trip_expense` (error), строка не переносится и не становится ручным расходом. Ручной расход: `line:{id}` + одна доля. Строка с доходом и расходом даёт оба объекта; нулевые строки пропускаются. Идемпотентность по legacy_line/legacy_group_key; overwrite=True только у Shadow.
- `migrate_invoice_links`: активные исходящие позиции со line -> InvoiceItem.income; входящие -> ExpenseInvoiceAllocation на долю с тем же legacy_line; позиции без line (отменённые) пропускаются и считаются.
- `migrate_finance --company ID [--dry-run]`: engine new - отказ; Run(kind=migrate, mode, params, summary: счётчики, суммы источников и созданного по (валюта, месяц), спорные строки, число открытых error-проблем); dry-run ничего не пишет кроме Run и печатает отчёт; apply - транзакция на заказ, затем счета; ошибка заказа -> Issue `migrate_error`, остальные продолжаются; статус success или needs_review. `resolve_finance_issue --issue ID --note` и `migration.resolve_issue`.
- Старые счета, платежи, rate_to_kzt, OrderService не меняются (проверка снимком до/после).
