## Реализация
- `create_expense` (ручной: категория из expense_category, дата - ввод пользователя с проверками 1.4.3, FX-снимок на expense_date, нет курса -> 409 rate_missing; без долей расход ждёт распределения, при переданных долях они проверяются; платёж и счёт расход не создают).
- `create_carrier_expense` (только вручную, блокировки Order -> Trip -> Expense; нужен перевозчик; amount = carrier_price, requires_full_allocation, carrier_price_snapshot; по умолчанию доли поровну по заказам рейса через `split_evenly`, копейки первому; пользовательские доли - ровно на сумму; `expense_exists` и по DB-уникальности при гонке; нулевая цена - без долей).
- `sync_trip_expense` (хук цены рейса при engine=new и sync_carrier_price): нет расхода или void или цена совпала - no-op; иначе в одной транзакции amount, snapshot, base_amount по сохранённому курсу, доли пропорционально (`split_proportionally`, наибольший остаток, Σ == amount), нулевая цена убирает доли, рост с нуля - доли по умолчанию; закрытый месяц - 409 / 400 / корректировка с аудитом; затем `refresh_invoice_variance`.
- `refresh_invoice_variance`: Σ активных связей со счетами != amount -> needs_review/invoice_variance (не блокирует, счета и платежи не меняются); совпало -> флаг снимается.
- `set_allocations` (замена долей, Σ <= amount, при полном - Σ == amount, нераспределённое допустимо, для перевозчика заказы из рейса, no-op при тех же долях, закрытый период, аудит), `void_expense` (доли остаются историей, закрытый период, идемпотентно).

## Решения/интерпретации для подтверждения
- Категория расхода перевозчику по умолчанию OTHER («Прочее»), можно передать другую (в справочнике нет «Перевозка»).
- У доли расхода перевозчика заполнены и заказ, и рейс: это одна доля, не две (нет двойного учёта).
- Расход с requires_full_allocation можно создать без долей (до распределения); проверка Σ == amount срабатывает при записи долей.
