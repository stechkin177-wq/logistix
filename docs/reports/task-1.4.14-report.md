- Число запросов не зависит от числа счетов (тест).

## Статусы исключённого (excluded, суммы в исходной валюте) и is_partial
- `no_rate` - нет курса на дату отчёта: в итоги базы не входит.
- `prior_base` - снимок счёта в другой базовой валюте: в итоги базы (`balance_base`, `overdue_base`, `carrying`, `unrealized`) не входит; эквивалент на дату отчёта показан справочно (`equivalent_base`) и не суммируется.
- `no_base_rate` - у счёта нет базового курса (выпущен до снимков): эквивалент на дату отчёта входит в `balance_base/overdue_base`, но `carrying_base` и нереализованная разница не считаются.
- Для оплат: `prior_base`, `no_base_rate` (оплата/счёт без базового курса или в другой базе) исключаются из реализованной разницы.
- Счёт в валюте, равной базовой, всегда пригоден (курс 1, разница 0).

## Оговорки и интерпретации (нужно подтверждение заказчика)
1. **Противоречие в брифе по prior_base.** Одно предложение требует показывать эквивалент на дату отчёта и для счетов «другой базовой эпохи», другое - итоги в базе только по пригодным записям и отдельный блок prior_base. Принято: `prior_base` из итогов базы исключён, эквивалент показан справочно внутри блока исключённого; `no_base_rate` (счёт вообще без снимка) эквивалент в итоги входит. Для оплат/неполноты введена третья причина `no_base_rate` помимо prior_base/no_rate (в брифе упомянуты две).
2. **as_of в прошлом** реконструирует состояние на дату: счета с `issue_date <= as_of`, оплаты `date <= as_of`, просрочка относительно `as_of`; отменённый позже счёт восстановить нельзя (учитывается текущий статус issued). `as_of` в будущем - 400.
3. **Нереализованная в сводке** - сумма дебиторской и кредиторской с учётом знака (out +, in -) в `fx_unrealized_base` плюс отдельные поля по направлениям; реализованная - за календарный месяц `today`. «Общего итога» реализованная+нереализованная нет.
4. **Закрытие периода**: снимок создаётся только при реальном закрытии (не при идемпотентном повторе); переоценка идёт по состоянию на конец месяца (счета/оплаты не позже последнего дня месяца).
5. **Excel**: пометки только на русском (как в 1.4.13); отдельного Excel «Оплаты» в проекте нет - реализованные разницы вынесены отдельным листом журнала операций. «Эквивалент в базе (курс, дата)» выведены тремя колонками (эквивалент, курс, дата курса).
6. Снимок строки `FxRevaluationLine` хранит `party_id`/`overdue`/статус в `flags`; в отчёте из снимка нет прежних KZT-полей (`issued_kzt` и т.п. = null) и использования лимита - они не восстанавливаются без пересчёта.
7. Кредитный лимит клиента по-прежнему считается в KZT по курсу счёта (`limit_usage_pct`), в базовую валюту не переводился.
8. Серилизатор счёта (`invoice_data`) новые снимковые поля не отдаёт (не требовалось); они доступны в БД и используются отчётами.
9. Страница «Периоды/снимки» в интерфейсе не добавлялась: снимки доступны через API (`/fx-revaluations/`, `?period=`).
