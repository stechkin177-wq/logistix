# Договоры и банковские реквизиты: единый источник данных, перенос, совместимость

Статус: решение принято исполнителем в рамках разрешённого шага 3 этапа 3 (владелец: «не удалять и не дублировать
существующие данные; сначала определить единый источник данных, обеспечить перенос и совместимость»).

## 1. Что есть сейчас (источники правды)

| Данные | Где лежат | Кто читает |
|---|---|---|
| Банк и IBAN клиента и перевозчика | поля `bank`, `iban` в `forwarding.Client` / `Carrier` (по одной паре) | карточка стороны, документы (`documents/context.py: _party`) |
| Банк и IBAN нашей стороны | поля `bank`, `iban` в `core.LegalEntity` | документы (`_entity`) |
| Договор | (а) текст `Order.contract_number`; (б) выданный документ `IssuedDocument(kind="contract", client)` | форма заказа, журнал документов |

Проблема: договор - два несвязанных места, у стороны нельзя хранить несколько счетов (по валютам).

## 2. Единый источник (решение)

**Банковские счета - только `BankAccount`.** Владелец - клиент, перевозчик или наше юрлицо (ровно один).
Старые столбцы `bank`/`iban` **остаются физически** (ничего не удаляется), но становятся **зеркалом счёта по умолчанию**:
пишутся только сервисом счетов и обновляются в той же транзакции при любом изменении счетов владельца.
Читатели (документы, прежние клиенты API) продолжают читать те же поля - и видят актуальный счёт по умолчанию.
Прежний путь записи (`PATCH` стороны с `bank`/`iban`) работает: значения превращаются в счёт по умолчанию (создаётся или
обновляется), зеркало остаётся согласованным. Второго экземпляра данных нет: источник - счета, поля - производное.

**Договоры - только `Contract`.** Сторона (клиент или перевозчик, ровно одна), номер, дата, срок действия, вид, название,
комментарий. Выданный по шаблону файл остаётся в `IssuedDocument` и не копируется: связь хранится в договоре
(`Contract.document`, необязательно): так таблицы документов не меняются. `Order.contract` и `Trip.contract` - необязательные ссылки. **`Order.contract_number` остаётся**:
при выборе договора заполняется из него (производное), у заказов без выбранного договора работает как раньше.

## 3. Перенос (идемпотентный, обратимый как noop, без удаления)

- Счета: для каждого клиента/перевозчика/юрлица с непустыми `bank` или `iban` создаётся один `BankAccount`
  (`is_default=True`, валюта не задана). Повторный запуск не создаёт дублей (проверка по владельцу и IBAN/банку).
- Договоры: из выданных документов `kind="contract"` с клиентом - `Contract(client, number, date=issue_date, document)`;
  из уникальных пар (клиент, `Order.contract_number`) без совпадающего договора - `Contract(source="imported")`;
  если номер совпал с выданным документом - один договор с обеими связями. Заказам с совпавшим номером проставляется
  `Order.contract`; текст `contract_number` не меняется.

## 4. Совместимость

- API сторон: поля `bank`, `iban` прежние; добавлено `accounts` (только чтение) - список счетов.
- API заказа: `contract_number` прежний; добавлено `contract` (необязательно).
- Документы: контекст читает зеркало; при выбранном договоре заказа в документ подставляются его номер и дата.
- Откат: удалить новые таблицы и поля безопасно - прежние данные не менялись (зеркало равно прежнему значению).

## 5. Не входит

Выбор счёта по валюте документа (счёт имеет поле валюты; подстановка по валюте - отдельный шаг), шаблоны договоров
с переменными из `Contract`, интеграция с банками, любые финансовые сущности.

## 6. Реализовано

Модели `BankAccount` и `Contract` (RLS), `Order.contract`, `Trip.contract`, `Contract.document`; миграции 0017
(схема) и 0018 (перенос, идемпотентный); API `/api/bank-accounts/`, `/api/contracts/`; в карточке клиента и
перевозчика - блок «Банковские счета» и вкладка «Договоры»; выбор договора в заказе (по клиенту) и в рейсе (по
перевозчику, после создания). Права - по разделу владельца (`clients`/`carriers`/`company`). Договор, выбранный в
заказах или рейсах, удалить нельзя (409 `contract_in_use`). Рейс при создании договор не принимает.
