# Этап 3B. Документы: Word-шаблоны, журнал выданных, PDF

Дата: 2026-11-01. Родительская спецификация: `2026-10-31-universal-logistics-platform-design.md`, раздел 7 (строка «Шаблоны документов»).
Этап 3 разбит на два цикла: 3A «Финансы» (готов) и **3B «Документы»** (этот документ).

## 1. Цель и границы

**Цель.** Дать экспедитору печатные документы по его данным: договор, заявка клиента, договор-заявка перевозчику, акт, счёт на оплату, CMR, письмо на бланке. Тексты принадлежат компании: она получает готовый стартовый набор, правит его в Word и загружает обратно.

**Входит.** Шаблоны `.docx` с метками Jinja и версиями; стартовый набор из семи образцов на русском; выдача документа (номер, фиксация данных); журнал выданных; скачивание DOCX и PDF; сумма прописью (ru/kk); настройки шаблонов; кнопки выдачи в заказе, счёте, рейсе и карточке клиента; пункт меню «Документы».

**Не входит.** Отправка документов письмом (этап 5, вместе с почтовым модулем); казахские стартовые шаблоны (после юридической проверки); вставка картинок (логотип, печать) как метки; электронная подпись; редактор шаблонов в браузере; хранение файлов в MinIO.

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Источник текстов | Word-шаблоны компании с метками + стартовый набор платформы | Формулировки договоров у каждой компании свои, юристы работают в Word |
| Отправка письмом | Не в 3B | Почта (ящики, привязка к заказу) - этап 5; иначе отправку пришлось бы переделывать |
| Хранение | Журнал выданных документов: номер, снимок данных, версия шаблона; файл собирается при скачивании | Выданный документ не меняется при правке заказа; MinIO не нужен, работает и на демо |
| Движок | `docxtpl` (python-docx + Jinja2) в песочнице | Метки в разбитых Word-ом кусках текста, циклы по таблицам; свой поиск-замена ломается |
| PDF | LibreOffice headless, отдельный процесс, таймаут | Единственный надёжный путь «Word → PDF» с сохранением вида |

## 3. Данные

Все модели - `TenantModel` с RLS (`EnableRLS`); приложение `documents`.

**`DocumentTemplate`** - компания, `kind` (`contract`, `order_request`, `carrier_order`, `act`, `invoice_print`, `cmr`, `letter`), `name`, `language` (`ru`/`kk`), `is_active`, `current_version` (ссылка на последнюю версию). Уникальность: компания + вид + язык среди активных. Стартовый набор копируется компании при создании (и миграцией для существующих компаний), идемпотентно, как справочники.

**`DocumentTemplateVersion`** - шаблон, `number` (1, 2, ...), `content` (`BinaryField`, не больше 2 МБ), `sha256`, `is_starter` (версия из стартового набора), `uploaded_by`, `created_at`. Неизменяема; загрузка создаёт новую версию и переводит на неё `current_version`. Откат к стартовой версии - новая версия с копией стартового файла.

**`IssuedDocument`** - компания, `kind`, `template_version`, `number`, `issue_date`, ссылки (необязательные, по виду): `client`, `order`, `trip`, `invoice`; `snapshot` (`JSONField` - полный контекст подстановки на момент выдачи), `language`, `created_by`, `created_at`. Не удаляется и не изменяется после создания (в API нет правки и удаления).

## 4. Привязка видов документов

| Вид | К чему | Номер | Условия |
|---|---|---|---|
| `contract` | клиент | новый (`Д-{year}-{index}`) | клиент существует |
| `order_request` | заказ | номер заказа | заказ не удалён |
| `carrier_order` | рейс | новый (`ЗП-{year}-{index}`) | у рейса есть перевозчик |
| `act` | счёт клиенту | новый (`АКТ-{year}-{index}`) | счёт выставлен (`issued`) |
| `invoice_print` | счёт клиенту | номер счёта | счёт выставлен |
| `cmr` | рейс | новый (`CMR-{year}-{index}`) | рейс не удалён, есть грузы |
| `letter` | свободное (необязательно заказ) | новый (`ИСХ-{year}-{index}`) | адресат, тема, текст (до 20 000 символов) |

Новые виды номеров добавляются в нумерацию ядра (`KINDS`, `DEFAULTS`); шаблоны номеров редактируются в настройках. Номер выдаётся в той же транзакции, что и запись журнала (без пропусков при откате).

## 5. Данные для подстановки (контекст)

Контекст строится сервисом из объектов компании и сохраняется в `snapshot`. Верхний уровень общий для всех видов, остальное - по виду.

- `doc`: `number`, `date`, `date_long` (дата вида «1 ноября 2026 г.», месяц словом на языке шаблона).
- `company` (юрлицо заказа/счёта, иначе юрлицо по умолчанию): `name`, `bin`, `address`, `bank`, `iban`.
- `client` / `carrier`: поля карточки контрагента (название, БИН/ИИН, адрес, банк, IBAN, телефон, email) и `contact` (первое контактное лицо: имя, телефон).
- `order`: `number`, `date`, `contract_number`, `client_ref`, `rate`, `rate_words`, `currency`, `payment_delay_days`, `comment`, `manager`, `consignments[]` (`name`, `weight_kg`, `volume_m3`, `pallets`, `load`/`unload` с `city`, `address`, `date`).
- `trip`: `number`, `price`, `price_words`, `currency`, `vehicle_plate`, `driver_name`, `orders[]`, `consignments[]`.
- `invoice`: `number`, `date`, `due_date`, `currency`, `vat_rate`, `items[]` (`title`, `amount_net`), `net`, `vat`, `gross`, `gross_words`.
- `letter`: `recipient`, `subject`, `body`.

Суммы - форматированные строки с разделителями и двумя знаками. «Прописью»: русский и казахский, валюта и дробная часть по справочнику валют (тенге/тиын и т.д.), падежи по числу. Если данных нет, метка даёт пустую строку, документ не падает. Полный справочник меток по видам отдаёт `GET templates/placeholders/`.

## 6. Правила

**Права.** Новый раздел `documents` (просмотр, создание, изменение, удаление). Администратор - всё; Менеджер, Бухгалтер, Диспетчер - просмотр и создание; Наблюдатель - просмотр. Загрузка версий и откат шаблона - `documents.update`; отключение шаблона - `documents.delete`. Выдача дополнительно требует доступа к исходному объекту (`orders.view`, `trips.view`, `finance.view`, `clients.view`); права проверяются на сервере.

**Загрузка шаблона.** Только `.docx`; размер до 2 МБ; проверяется структура OOXML, размер после распаковки (до 20 МБ), отсутствие макросов (`vbaProject`) и внешних связей. Затем пробная сборка на тестовом контексте в `StrictUndefined`: неизвестная метка или ошибка синтаксиса дают 400 `template_invalid` с названием метки и номером строки. Сборка идёт в песочнице Jinja (`SandboxedEnvironment`): доступ к внутренностям Python запрещён.

**Выдача.** Требуется активный шаблон вида и языка компании (иначе `template_missing`). Состояние источника проверяется под блокировкой (`source_not_ready`: счёт не выставлен/отменён, у рейса нет перевозчика). Каждая выдача - новая запись и новый номер; отдельного «режима черновика» нет.

**Скачивание.** DOCX собирается из снимка и версии шаблона. PDF - конвертация этого DOCX в LibreOffice: отдельный процесс с изолированным профилем, таймаут 60 секунд, ограничение одновременных конвертаций (блокировка), результат не кэшируется на диск после ответа. Нет LibreOffice или сбой - `pdf_unavailable`, DOCX работает; `GET capabilities/` сообщает `pdf_available`.

**Язык.** В 3B стартовые шаблоны только русские; поле `language` готовит почву под казахские. Сумма прописью и названия месяцев зависят от `language` шаблона.

## 7. API

Префикс `/api/documents/`, `ModuleRequired("forwarding")`, единый формат ошибок `{detail, code}`.
- `GET templates/`; `POST templates/{id}/versions/` (multipart, поле `file`); `GET templates/{id}/download/`; `POST templates/{id}/reset/`; `PATCH templates/{id}/` (`is_active`, `name`); `GET templates/placeholders/?kind=`.
- `GET issued/` (фильтры `kind`, `client`, `order`, `trip`, `invoice`, `date_from`, `date_to`, `search`; постранично); `GET issued/{id}/`; `POST issued/`; `GET issued/{id}/download/?format=docx|pdf`.
- `GET capabilities/`.
- Коды ошибок: `template_missing`, `template_invalid`, `template_too_large`, `source_not_ready`, `pdf_unavailable`, `letter_invalid`.

## 8. Интерфейс (ru/kk)

- Настройки → «Шаблоны документов»: таблица шаблонов, загрузка версии, скачивание текущего, откат к стартовому, справочник меток по виду.
- Кнопки выдачи: заказ («Заявка клиента»), счёт («Счёт на оплату», «Акт»), рейс («Договор-заявка перевозчику», «CMR»), карточка клиента («Договор»). Кнопка выдаёт документ и скачивает DOCX; PDF - вторая кнопка (скрыта, если `pdf_available = false`).
- Пункт меню «Документы» (право `documents.view`): журнал выданных с повторным скачиванием и форма «Письмо на бланке».
- Все тексты через i18n ru/kk.

## 9. Тестирование

- Изоляция компаний через API, поиск и скачивание; отдельный тест под ролью приложения с RLS на всех новых таблицах (`check_rls`).
- Права: каждая роль и действие; доступ к исходному объекту.
- Сборка: метки, циклы по грузам и позициям, условия, сумма прописью (ru/kk, границы: 0, 1, 11-14, 21, миллионы, копейки), снимок не меняется после правки заказа/счёта.
- Безопасность шаблонов: макросы, внешние связи, файл больше лимита, «бомба» при распаковке, вредоносные метки (`__class__`, `config`, вызовы), неизвестные метки.
- Нумерация без дублей при одновременной выдаче; откат транзакции не расходует номер.
- PDF: успешная конвертация (если LibreOffice есть в окружении), недоступность, таймаут.
- Миграции: стартовый набор у существующих компаний, идемпотентность.

## 10. Риски и допущения

- Стартовые тексты - образцы; юридическая проверка обязательна до использования клиентами (как и в родительской спецификации).
- Образ сервера тяжелее на размер LibreOffice и шрифтов (включая символы казахского алфавита); на демо Vercel PDF недоступен.
- Шаблон выполняется как код Jinja; безопасность опирается на песочницу, лимиты и проверки при загрузке - это главная зона ревью.
- Хранение шаблонов в БД ограничено 2 МБ на версию; старые версии не удаляются (нужны для выданных документов).
