# Этап 3A. Финансы: счета, оплаты, долги, курсы

Дата: 2026-11-01. Родительская спецификация: `2026-10-31-universal-logistics-platform-design.md`, раздел 7.
Этап 3 разбит на два цикла: **3A «Финансы»** (этот документ) и 3B «Документы» (шаблоны, PDF/DOCX, письма; отдельный цикл после 3A).

## 1. Цель и границы

**Цель.** Дать экспедитору учёт денег поверх готового экспедиторского контура: выставлять счета клиентам, принимать счета перевозчиков, отмечать оплаты вручную, видеть долги и просрочку, считать итоги в тенге при заказах в разных валютах.

**Входит.** Выставленные счета (`out`) и полученные счета перевозчиков (`in`), оплаты (в том числе частичные), курсы валют, ставки НДС на счёте, журнал операций (доходы и расходы по строкам заказа), долги по клиентам и перевозчикам, предупреждение о превышении кредитного лимита, финансовые плитки дашборда, раздел «Финансы» и блок «Счета и оплаты» в карточке заказа.

**Не входит.** Документы и PDF (3B), онлайн-эквайринг, импорт банковских выписок, ЭСФ и ЭЦП, справочник категорий (категория остаётся свободным текстом, как в строках заказа), автоматическое распределение цены рейса по заказам, оплата одного платежа сразу несколькими счетами.

## 2. Принятые решения (с обоснованием)

| Вопрос | Решение | Почему |
|---|---|---|
| Валюты | Суммы хранятся в валюте документа; рядом курс к тенге на дату; отчёты считаются в тенге с разбивкой по валютам | Так считают экспедиторы: видна курсовая разница, не теряется исходная сумма |
| Состав счёта клиенту | Из выбранных строк дохода заказа; на заказ можно несколько счетов (аванс, итог) | Нужны авансы и поэтапные счета; суммы счетов сверяются с доходом заказа |
| Счёт перевозчика | Счёт по рейсу + привязка к строкам расхода заказов рейса | Прибыль заказа совпадает с тем, что реально платят; консолидация поддерживается |
| НДС | Строки заказа без НДС; ставка выбирается на счёте из справочника ставок | Работает и для плательщиков НДС, и для неплательщиков; прибыль не искажается налогом |
| Оплата | К одному счёту; несколько оплат на счёт | Просто и проверяемо; один платёж на несколько счетов вносится отдельными записями с общим «номером платёжки» |
| Архитектура | Новое приложение `finance`; читает `forwarding` через сервисные функции, `forwarding` о нём не знает | Модульный монолит по родительской спецификации |

## 3. Данные

Все модели наследуют `TenantModel` (поле `company`, RLS FORCE, политика как у остальных таблиц компаний); счета и оплаты имеют мягкое удаление и попадают в корзину и аудит.

**`ExchangeRate`** - компания, валюта (из справочника `currency`), дата, курс к тенге (`Decimal(18,6)`, больше 0). Уникальность: компания + валюта + дата. Для тенге курс всегда 1, запись не создаётся. Поиск курса на дату: последняя запись с датой не позже нужной. Если записи нет, операция в иностранной валюте отклоняется с понятной ошибкой.

**`Invoice`**
- `direction`: `out` (клиенту) или `in` (от перевозчика).
- `number`: для `out` присваивается при выставлении по шаблону нумерации `invoice_out` (`СЧ-{year}-{index}`); для `in` - внутренний номер `invoice_in` (`ПС-{year}-{index}`) плюс поле `external_number` (номер, который прислал перевозчик).
- `client` (для `out`) или `carrier` (для `in`), ровно одно из двух, по направлению; `order` (необязательно для `in`), `trip` (для `in` по рейсу).
- `currency`, `vat_rate` (ссылка на справочник «ставки НДС»; «без НДС» - ставка 0 с признаком), `issue_date`, `due_date`, `rate_to_kzt` (фиксируется при выставлении), `status`, `comment`.
- `total_net`, `total_vat`, `total_gross` - хранятся, пересчитываются сервисом при выставлении, `Decimal(14,2)`.
- Статусы: `draft`, `issued`, `cancelled`. Статусы «частично оплачен / оплачен / просрочен» производные (см. раздел 4).

**`InvoiceItem`** - счёт, название, сумма без НДС (`Decimal(14,2)`, не меньше 0), ссылка на `forwarding.OrderService` (для `out` - строка дохода, для `in` - строка расхода), для рейсового счёта `in` также ссылка на рейс. Ограничение: одна строка заказа входит не более чем в один активный (не отменённый, не удалённый) счёт того же направления.

**`Payment`** - счёт, дата, сумма в валюте счёта (больше 0), `rate_to_kzt` на дату платежа, способ (`bank`, `cash`, `other`), `payment_ref` (номер платёжки), комментарий. Суммы оплат по счёту не могут превышать `total_gross`. Оплата возможна только по выставленному счёту.

**Права.** Раздел `finance` уже есть в каталоге. Добавляются два действия: `finance.override_limit` и `finance.cancel_invoice`. Администратору и Бухгалтеру - оба, остальным - нет. Менеджеру остаётся `finance.view`. Права проверяются на сервере.

## 4. Правила

**Жизненный цикл счёта.**
- `draft`: можно править позиции, ставку, срок; можно удалить.
- `issue`: в одной транзакции проверяются курс, валюта, строки; присваивается номер (для `out`), фиксируются `rate_to_kzt` и суммы, статус `issued`. Нумерация не теряет номера при откате.
- После выставления позиции, ставка, валюта и суммы не меняются; правятся срок оплаты, `external_number`, комментарий.
- `cancel` (право `finance.cancel_invoice`): возможно, если по счёту нет оплат; строки заказа освобождаются; счёт остаётся в журнале.

**Производные значения.**
- `paid` = сумма оплат; `balance` = `total_gross − paid`.
- Отображаемый статус: `draft`; `cancelled`; `paid` (баланс 0); `partial` (0 < оплачено < всего); `overdue` (баланс > 0 и `due_date` раньше сегодняшней даты в часовом поясе компании); иначе `issued`. Просрочка - вычисление при запросе, не хранимый флаг.
- Срок оплаты по умолчанию: `issue_date` + дни отсрочки заказа; пользователь может изменить.

**Валюта.** Валюта счёта совпадает с валютой заказа (для рейсового счёта `in` - с валютой, общей для включённых строк). Любой иной случай - ошибка. Если `Order.currency` не задана, берётся тенге.

**Деньги в тенге.**
- Сумма счёта в тенге = `total_gross × rate_to_kzt` (курс счёта).
- Долг в тенге = остаток × курс счёта.
- Оплата в тенге = сумма × курс на дату платежа.
- Курсовая разница по оплате = сумма × (курс платежа − курс счёта); для `out` положительная разница - прибыль, для `in` - убыток. В отчётах показывается отдельной строкой «Курсовая разница» и в прибыль заказа не входит.
- Все расчёты - `Decimal`, одно место округления до копеек (`ROUND_HALF_UP`).

**Лимит кредита.** При выставлении счёта `out` считается долг клиента (остатки выставленных счетов в тенге) плюс новый счёт в тенге. Если больше `Client.credit_limit` (0 - лимит не задан), выставление отклоняется ошибкой `credit_limit_exceeded`, которую можно обойти только действием `issue` с флагом `override_limit=true` при наличии права `finance.override_limit`; причина (обязательный текст) записывается в аудит.

**Сверка с заказом.** Сумма активных счетов `out` по заказу не может превышать доход заказа (сумма `income` его строк). Разрешено меньше (счета выставляются поэтапно). В карточке заказа показывается «выставлено / доход / оплачено».

**Рейсовый счёт перевозчика.** Выбирается рейс; система показывает строки расхода заказов рейса. Для заказа без строки перевозки действие «Создать расход из цены рейса» создаёт строку расхода (категория «Перевозка»); для консолидированного рейса предлагается деление поровну, пользователь может изменить суммы, но их итог должен совпасть с ценой рейса. Автоматически ничего не создаётся.

## 5. API

Префикс `/api/finance/`. Единый формат ошибок и пагинации ядра, права по каталогу, постраничные списки.
- `invoices/` - список с фильтрами (направление, статус, клиент/перевозчик, заказ, рейс, период, просроченные), создание и правка черновика, `invoices/{id}/issue/`, `invoices/{id}/cancel/`, `invoices/{id}/payments/` (создание и список).
- `payments/` - общий журнал оплат с фильтрами; удаление оплаты (с аудитом) пересчитывает баланс.
- `operations/` - журнал доходов и расходов по строкам заказа: фильтры период, категория, клиент, заказ; итоги «доход / расход / разница» в тенге; `operations/export/` - Excel (по образцу экспорта заказов, с очисткой недопустимых символов).
- `debts/clients/`, `debts/carriers/` - выставлено, оплачено, остаток, просрочено (в тенге и по валютам); для клиентов - лимит и процент использования.
- `rates/` - справочник курсов.
- `summary/` - плитки дашборда: долг клиентов, просрочено, к оплате перевозчикам, прибыль и маржа за месяц в тенге.
- Нумерация, оплаты и выставление используют блокировки строк (`select_for_update`) в одной транзакции: гонки не должны давать лишних номеров или превышения баланса.

## 6. Интерфейс (ru/kk)

- Раздел «Финансы» в меню (виден при `finance.view`): «Счета», «Оплаты», «Операции», «Долги», «Курсы».
- Форма счёта: заказ или рейс, отметка строк, ставка НДС, срок, блок «без НДС / НДС / всего», кнопки «Сохранить черновик» и «Выставить»; предупреждение о лимите с запросом причины.
- В карточке заказа блок «Счета и оплаты».
- Плитки дашборда: «Долг клиентов», «Просрочено», «К оплате перевозчикам».
- Все тексты через i18n; суммы форматируются по локали; доступность и компактность таблиц как в остальном интерфейсе.

## 7. Ошибки

Единый формат API с кодами: `rate_missing`, `currency_mismatch`, `item_already_invoiced`, `payment_exceeds_balance`, `invoice_not_editable`, `invoice_has_payments`, `invoice_exceeds_order_income`, `credit_limit_exceeded`, `forbidden`. Сообщения на русском и казахском.

## 8. Тестирование

- Изоляция компаний через API, поиск и экспорт; отдельный тест под ролью приложения с RLS на всех новых таблицах (`check_rls` должен их охватывать).
- Права: каждая роль и каждое действие, включая `override_limit` и `cancel_invoice`.
- Арифметика: НДС, округление, частичные оплаты, курсы (поиск по дате, отсутствие курса), курсовая разница, долг в тенге.
- Ограничения: строка не входит в два счёта, счёт не превышает доход заказа, оплата не превышает остаток, правки выставленного счёта запрещены.
- Параллелизм: одновременное выставление (номера без дублей), одновременные оплаты (баланс не уходит ниже нуля).
- Граница просрочки в часовом поясе компании; лимит кредита (предупреждение, обход с правом и без).
- Миграции: новые таблицы с RLS и индексами по компании и датам; существующие данные не затрагиваются.

## 9. Риски и допущения

- Курсы вводятся вручную, автоматическая загрузка курсов НБ РК не входит (можно добавить отдельно).
- Курсовая разница - информационная, в бухгалтерский учёт не передаётся.
- Категории доходов и расходов остаются свободным текстом до отдельного решения.
- Существующие строки заказов, созданные до этапа 3, остаются без счетов; сверка «выставлено / доход» показывает их как неоплаченный доход.
