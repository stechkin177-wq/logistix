# Этап 3A. Финансы: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** счета (клиентам и от перевозчиков), оплаты, курсы, долги, журнал операций и финансовые плитки дашборда поверх готового экспедиторского контура.

**Architecture:** новое приложение `backend/apps/finance` читает `forwarding` (заказы, рейсы, `OrderService`) и ядро (нумерация, справочники, аудит, корзина), а `forwarding` о нём не знает. Деньги считаются на сервере в `Decimal` одним модулем `money.py`. Фронтенд: страница `/finance` с вкладками и блок «Счета и оплаты» в карточке заказа.

**Tech Stack:** Django 5, DRF, PostgreSQL 16 (FORCE RLS), pytest; React 19, TypeScript, TanStack Query, i18next (ru/kk), vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-finance-3a-design.md` (читать целиком вместе с планом).

## Global Constraints

- Все новые модели наследуют `TenantModel` (`apps.core.models`); счета и оплаты ещё `SoftDeleteModel`. Каждая новая таблица получает `EnableRLS("finance.<Model>")` в миграции; `manage.py check_rls` должен проходить.
- Права по каталогу `<раздел>.<действие>`; раздел `finance`; новые коды: `finance.override_limit`, `finance.cancel_invoice`. Права проверяются на сервере.
- Суммы: `Decimal`, `max_digits=14, decimal_places=2` (курс `Decimal(18,6)`), округление до копеек одним методом `ROUND_HALF_UP` в `apps/finance/money.py`.
- Базовая валюта - тенге (`BASE_CURRENCY_CODE = "KZT"` из `apps.forwarding.orders.services`); курс KZT всегда 1.
- Ошибки API: `{"detail": "...", "code": "..."}` через `FinanceError(code, detail)` (Задача 2). Коды: `rate_missing`, `currency_mismatch`, `party_mismatch`, `item_already_invoiced`, `payment_exceeds_balance`, `invoice_not_editable`, `invoice_has_payments`, `invoice_exceeds_order_income`, `credit_limit_exceeded`.
- Тексты интерфейса только через i18n, ключи в `web/src/shared/i18n/ru.json` и `kk.json` одновременно.
- Модуль доступа: все API требуют `ModuleRequired("forwarding")` (как `OrderServiceViewSet`).
- Тесты бэкенда: `cd backend && python -m pytest <path> -v` (нужен PostgreSQL, как в существующем CI). Фронтенд: `cd web && npx vitest run <file>`, `npm run lint`, `npx tsc -b`.
- Не использовать `git fetch --depth=1`; коммиты заканчиваются строками `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` и `Claude-Session: https://claude.ai/code/session_01TJdsug1NTZLaDzZhyYrtpE`.

## Review Focus

1. Заказ в USD, курса на дату нет: выставление и оплата дают 400 `rate_missing`, а не 500.
2. Две одновременные оплаты в сумме больше остатка: проходит ровно одна (Задача 6).
3. Счёт клиента A с позицией из заказа клиента B, либо со строкой отменённого или удалённого заказа: 400 `party_mismatch` / `item_already_invoiced`, а не молчаливый успех (Задача 5).
4. Сумма позиции на границе округления (0.005) и значение больше `max_digits`: корректный результат или 400, не 500 (Задача 4, 7).
5. Текст с управляющими символами в названии позиции не ломает выгрузку операций в Excel (Задача 9).
6. Клиент без лимита (0) и пустая история: долги и плитки возвращают нули, а не ошибку деления (Задача 10).
